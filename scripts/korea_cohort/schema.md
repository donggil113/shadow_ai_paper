# Korean health-screening cohort — unit-level input schema (v1.0)

Binding for `scripts/korea_cohort/prepare_korea_cohort.py` (which validates
every rule below and exits with code 3 on any violation). One row per
**screening exam**. File: `<data-root>/screening_exams.csv`, UTF-8, comma
separated, header row, no comment lines. The file is pseudonymised
unit-level data: it lives on the data custodian's server only and is never
committed; only aggregates with `>= 10` units per cell ever leave the server
(see README, "Privacy").

The synthetic pytest fixture `tests/fixtures/korea_cohort/screening_exams_fixture.csv`
(generated by `make_fixture.py`, **synthetic, never reported**) follows this
schema exactly.

## Keys

| column | type | allowed values | missing | meaning |
|---|---|---|---|---|
| `subject_id` | string | non-empty; pseudonymised (no resident registration number, no name) | no | person identifier, stable across exams |
| `exam_date` | string | `YYYY-MM-DD`, valid calendar date | no | date of the screening exam |
| `centre_id` | string | non-empty; pseudonymised screening centre / examining physician | no | the decision maker: leniency instrument `Z` |

## Demographics

| column | type | allowed values | missing | meaning |
|---|---|---|---|---|
| `age` | integer | 19–110 | no | age at the exam (years) |
| `sex` | string | `F`, `M` | no | sex as recorded |

## Screening panel (covariates `X`)

Numeric covariates are validated against a *plausible* range (values outside
it are schema violations, not outliers to be clipped). Missing values are
allowed; they are median-imputed and flagged (`m_<name>` indicator) by the
preparation script. Nothing downstream of the follow-up decision may be a
covariate.

| column | type | unit / allowed values | plausible range | meaning |
|---|---|---|---|---|
| `bmi` | float | kg/m² | 10–80 | body-mass index |
| `sbp` | float | mmHg | 50–300 | systolic blood pressure |
| `dbp` | float | mmHg | 30–200 | diastolic blood pressure |
| `fasting_glucose` | float | mg/dL | 20–1000 | fasting plasma glucose |
| `total_cholesterol` | float | mg/dL | 50–1000 | total cholesterol |
| `ldl` | float | mg/dL | 0–800 | LDL cholesterol (measured or Friedewald) |
| `hdl` | float | mg/dL | 5–200 | HDL cholesterol |
| `triglycerides` | float | mg/dL | 10–5000 | triglycerides |
| `creatinine` | float | mg/dL | 0.1–30 | serum creatinine |
| `egfr` | float | mL/min/1.73 m² | 0–300 | estimated GFR (state the equation in the data note) |
| `ast` | float | IU/L | 1–5000 | aspartate aminotransferase |
| `alt` | float | IU/L | 1–5000 | alanine aminotransferase |
| `ggt` | float | IU/L | 1–5000 | gamma-glutamyl transferase |
| `haemoglobin` | float | g/dL | 3–25 | haemoglobin |
| `smoking_status` | integer | `0` never, `1` former, `2` current | — | questionnaire |
| `alcohol_freq` | integer | `0` none, `1` ≤ 1/month, `2` 2–4/month, `3` 2–3/week, `4` ≥ 4/week | — | questionnaire (drinking frequency) |
| `exercise_freq` | integer | 0–7 | — | days per week with ≥ 30 min of moderate/vigorous exercise |
| `fh_diabetes` | integer | `0`/`1` | — | family history: diabetes |
| `fh_hypertension` | integer | `0`/`1` | — | family history: hypertension |
| `fh_cvd` | integer | `0`/`1` | — | family history: stroke / heart disease |
| `fh_cancer` | integer | `0`/`1` | — | family history: cancer |

## Decision, outcome, score, follow-up

| column | type | allowed values | missing | meaning |
|---|---|---|---|---|
| `followup_test_ordered` | integer | `0`/`1` | no | **T**: 1 if a confirmatory / downstream test was ordered at this exam. Used for the Γ analysis. The truth-batch cohort with `T ≡ 1` (everyone screened, everyone followed) is the special case in which the Γ analysis is undefined and only the containment analysis runs. |
| `outcome` | integer | `0`/`1`/empty | only where `followup_test_ordered == 0` | **Y**: the target event within the follow-up window (`--window-days`, default 365 d) after `exam_date`. In the batch cohort it is recorded for every row. Empty is permitted only for `T = 0` rows (selective-labels variant) and marks the row as censored. |
| `public_model_score` | float | any real (a probability or a logit); empty allowed | column optional | risk score of a model developed on public / US data, evaluated on this unit's panel. Rows without it are excluded from the containment analysis only. |
| `followup_days` | integer | ≥ 0 | no | days from `exam_date` to the earliest of: the target event, loss to follow-up, death from another cause, administrative end of follow-up (time at risk). `outcome == 1` requires `followup_days <= window_days`. |

## Validation rules (exit code 3 on any violation)

1. all required columns present (`public_model_score` is the only optional column);
2. keys non-empty; `exam_date` well formed and a real date;
3. `age` integer in 19–110; `sex` in {F, M};
4. every numeric covariate numeric-or-empty and inside its plausible range;
   ordinal / flag covariates inside their value sets or empty;
5. `followup_test_ordered` in {0, 1}, never empty; `outcome` in {0, 1} or
   empty, and never empty where `followup_test_ordered == 1`;
6. `followup_days` non-negative integer, never empty; `outcome == 1` implies
   `followup_days <= window_days`;
7. `public_model_score`, if present, numeric or empty.

## Processing rules (in this order)

1. **Dedup**: one exam per subject per calendar year — keep the earliest
   `exam_date` (ties: first row in file order). Korean national screening is
   biennial / annual, so a subject-year is the unit.
2. **Window**: rows with no recorded event (`outcome` 0 or empty) and
   `followup_days < window_days` cannot be classified within the window and
   are dropped. The counts dropped by each rule are written to the sidecar.

## Derived variables (prepared file)

| column | derivation |
|---|---|
| `exam_year` | calendar year of `exam_date` |
| `Z` | integer code of `centre_id` (levels listed in the sidecar as `Z_levels`, sorted) |
| `T` | `followup_test_ordered` |
| `Y_full` | `outcome` as float, `NaN` where empty |
| `Y_obs` | `Y_full` where `T == 1`, `NaN` otherwise (what a selective-labels method may see) |
| `public_model_score`, `followup_days` | copied |
| `x_age`, `x_sex_male`, `x_<covariate>` | z-scored covariates after median imputation (`sex_male = 1{sex == M}`); means / stds / medians in the sidecar |
| `m_<covariate>` | 1 where the covariate was missing (only for covariates with any missingness) |

The sidecar (`<prepared stem>.json`) carries `data_source` (`real` or
`synthetic`), the input file's SHA-256, the rules applied, the feature list,
the standardisation record and aggregate counts (`counts`, `cohort`,
`per_centre`, `per_year`, `per_centre_by_T`) under the small-cell rule.
